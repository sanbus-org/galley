# WebAssembly

Galley-generated parsers can be consumed through a zero-dependency
WebAssembly module built from the same C API
([`bindings/c/galley.h`](https://github.com/sanbus-org/galley/blob/main/bindings/c/galley.h)).
The package in
[`bindings/js/wasm`](https://github.com/sanbus-org/galley/tree/main/bindings/js/wasm)
binds the runtime-neutral
[`bindings/js/core`](https://github.com/sanbus-org/galley/tree/main/bindings/js/core)
(`Session`, `Node`, diagnostics, tree editing — shared with the Node,
Deno, and Bun bindings) to a WASI reactor module, with no native
dependencies beyond the built parser module. It runs anywhere
WebAssembly runs.

A complete, runnable consumer lives in
[`examples/js/wasm`](https://github.com/sanbus-org/galley/tree/main/examples/js/wasm);
it is built and executed by CI on every push, byte-for-byte identical in
output to every other example.

Requires Node 18. No extra permissions and no WASI runtime: the adapter
embeds a minimal `wasi_snapshot_preview1` stub (real entropy and clocks;
filesystem calls report unavailable — the file is read by the host and
parsed from memory).

## Getting Started

Build the parser and wasm module for a directory containing `ll.grm`
and `config.zig`:

```sh
cd examples/js/wasm
GALLEY_CHECKOUT=/path/to/galley npm install
GALLEY_CHECKOUT=/path/to/galley npx galley-js-wasm .
npx tsx demo.ts
```

The build generates the parser (`--emit-metadata`), compiles the reactor
module through Galley's generic consumer build file (`-Dwasm`), and copies
`libgalley-js-wasm.wasm` next to your grammar. Import the bindings
from that directory:

```ts
import { Session, version, hasAst } from "galley-js-wasm";
```

`ZIG_EXECUTABLE` selects zig. Under Node the module auto-initializes
synchronously on first use; elsewhere (browsers) call `await init()` first
— `await init({ url })` or `await init({ bytes })` — then use the
synchronous `Session` API. `initSync()` is available for Node-only scripts.

## Procedures

Hook files work exactly like the Node bindings (`export function
reduction_<Var>(args)` / `export function hook_<name>(args)` in
`procedures.ts`, dispatched through the wasm `galley_js_dispatch` import
generated by `galley-js-core/build/shim.mjs`). Under Node `procedures.*`
in the language directory is auto-discovered via `require()`; elsewhere
register explicitly with `installProcedures` from `galley-js-core` before
parsing.

## Tests

```sh
cd examples/js/wasm
npm install
node ../../../bindings/js/wasm/tests/test_bindings.mjs
```

The suite mirrors `bindings/js/node/tests/test_bindings.mjs` behavior by
behavior.
